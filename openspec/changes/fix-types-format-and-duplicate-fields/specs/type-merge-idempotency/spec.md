## Purpose

保证类型合并逻辑（allOf/anyOf/oneOf 展开）具备幂等性：同一字段类型对象被多次渲染（例如被多个接口共享引用）时，每次渲染输出完全一致，不会在嵌套对象字面量中累积重复字段。

## ADDED Requirements

### Requirement: 类型合并幂等

生成器在对字段执行 allOf/anyOf/oneOf 与子属性合并时 SHALL 具备幂等性：对同一字段类型对象的多次取值操作 MUST 输出相同的类型内容，且 MUST NOT 因多次合并而向该对象的子属性列表中重复追加条目。

#### Scenario: 共享字段被两个接口渲染

- **WHEN** 文档中接口 A（响应包装类型）与接口 B（数据类型）共享同一个含 allOf 子结构的字段（如 `summary`）
- **THEN** 两个接口生成的声明中该字段的子属性各出现一次，先渲染与后渲染的输出内容完全一致

#### Scenario: 单接口内 allOf 合并

- **WHEN** 某字段 schema 为 `{ allOf: [X] }`（X 含 5 个属性，字段自身无 properties）
- **THEN** 该字段生成的内联对象类型恰好包含这 5 个属性，每个属性仅出现一次

### Requirement: 嵌套字段按名去重

生成嵌套对象字面量时，生成器 SHALL 按字段名对同级子属性去重（后出现者覆盖先出现者），与顶层接口字段的去重行为保持一致，作为幂等性的兜底保障。

#### Scenario: 子属性列表存在同名条目

- **WHEN** 某嵌套对象的子属性列表中因数据来源合并出现同名条目（如 `request_count` 出现两次）
- **THEN** 生成的类型中该属性仅保留一个声明
